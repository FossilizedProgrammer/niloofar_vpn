# نیلوفر وی‌پی‌ان (Niloofar VPN)

[English](README.md) · [فارسی](README.fa.md) · **Русский** · [Español](README.es.md)

Android-клиент для движка Firefox VPN из `../firefox-vpn-go`. Движок на Go
кросс-компилируется в `libffvpn.so`, запускается из `nativeLibraryDir` и
подключается к свободному выходу Firefox.

## Как он подключается

- **Режим VPN (по умолчанию).** Приложение открывает интерфейс TUN, а
  `libc2tun.so` (tun2socks) превращает каждый пакет этого телефона в соединение
  SOCKS5 с движком и дальше в выбранный выход Firefox. Со стороны телефона это
  обычный системный VPN: покрыты все приложения, и нигде не нужно вписывать
  прокси.
- **Режим прокси.** Без системного VPN и без окна согласия: работают только
  локальные слушатели движка SOCKS (1080) и HTTP (1081) — для приложений,
  которые вы сами на них направите.

### Почему для раздачи другим устройствам используются порты прокси

`VpnService` пропускает только трафик приложений на том устройстве, которое
создало туннель. Android не даёт приложению маршрутизировать через свой VPN
ноутбук по раздаче или второй телефон, поэтому при включении раздачи
слушатели движка привязываются к `0.0.0.0`, а другое устройство прописывает
себе прокси `<phone-ip>:1080` (SOCKS) или `<phone-ip>:1081` (HTTP). Трафик
по-прежнему выходит с телефона через тот же туннель; прокси — только способ
передать его этому устройству, потому что другого способа Android не
разрешает. То есть это VPN, а не «просто прокси»; режим прокси — отдельный
вариант, который можно выбрать вместо него.

## Возможности

- Подключение в одно касание: приложение получает список выходов, проверяет
  все граничные узлы, выбирает самый быстрый из тех, что реально пропускают
  трафик, и только потом показывает «Подключено».
- **Режим VPN** — открывается интерфейс TUN, и `libc2tun.so` (tun2socks)
  направляет трафик устройства в слушатель SOCKS5 движка.
- **Режим прокси** — без системного VPN и без окна согласия: работают только
  локальные слушатели SOCKS/HTTP — для приложений, которые вы сами на них
  направите.
- **Раздача по сети** — слушатели привязываются к `0.0.0.0`, поэтому другие
  устройства в той же Wi-Fi/точке доступа могут использовать
  `SOCKS <ip>:1080` или `HTTP <ip>:1081`.
- Keep-alive: локальный слушатель проверяется раз в минуту, и сеанс, который
  перестал отвечать, пересобирается сам — мёртвый туннель не остаётся
  включённым.
- Вход на собственной странице Mozilla внутри приложения: почта, пароль,
  двухфакторный код, письмо-подтверждение и проверка на грани Mozilla — всё
  делает её страница, а сеанс хранится, пока Mozilla его не подтвердит.
- Несколько аккаунтов на устройстве с переключением в одно касание, квота для
  каждого и подсказка по созданию аккаунта, открывающая страницу регистрации
  Mozilla.
- Живые показатели скорости и задержки, карточка журнала в настройках: она
  показывает объём журнала, копирует его в буфер обмена или очищает — строки
  остаются в памяти и никогда не показываются и не пишутся на диск.
- Интерфейс на английском/персидском/русском/испанском с выбором языка в
  приложении и песочная иконка-розетка.

## Сборка

Требования: JDK 17+ (здесь используется 21), Android SDK с build-tools 35 и
NDK 26.3.11579264, Go для движка.

```sh
./tools/build-apks.sh
```

Скрипт запускает `assembleRelease` и копирует разделённые APK в `dist/`. Та же
сборка идёт на GitHub: `.github/workflows/build-apks.yml` собирает каждый push,
pull request и тег. Push в `main` обновляет релиз **Latest build**, а тег
создаёт нумерованный релиз, поэтому APK в разделе Releases никогда не старее
`main`; каждый запуск также прикладывает их к запуску как артефакт
`NiloofarVPN-apks`. Бинарные файлы в репозитории не хранятся.

| Файл | ABI |
| --- | --- |
| `dist/NiloofarVPN-1.1.0-armeabi-v7a.apk` | 32-битный ARM |
| `dist/NiloofarVPN-1.1.0-arm64-v8a.apk` | 64-битный ARM |
| `dist/NiloofarVPN-1.1.0-universal.apk` | оба |

Релизные сборки подписаны отладочным ключом, чтобы ставиться сразу; перед
публикацией замените `signingConfig` в `app/build.gradle.kts` на настоящий
ключ.

### Зависимости и сеть

`settings.gradle.kts` сначала обращается к зеркалам Maven Tencent и Myket, так
как `dl.google.com` с этой машины нестабилен. Пользовательский
`~/.gradle/gradle.properties` задаёт SOCKS-прокси, которым Java не умеет
пользоваться, поэтому скрипт сборки передаёт `-DsocksProxyHost=` и ещё
очищает переменные окружения прокси.

### Пересборка движка

```sh
./tools/ffvpn/build-android.sh
```

Скрипт копирует `../firefox-vpn-go` во временный каталог, применяет патчи из
`tools/ffvpn/` (соль quick-stretch v2, кэшированный токен сеанса,
`--list-countries --json`, таймаут TLS-рукопожатия, запрос ответа на картинку)
и кросс-компилирует под обе ABI через clang из NDK с cgo, чтобы использовался
резолвер Android.

## Ограничения

- Устройства, которым раздаётся соединение, идут через порты прокси, а не через
  туннель: VPN в Android не покрывает клиентов точки доступа, поэтому устройство
  в вашей раздаче должно вручную прописать прокси `<phone-ip>:1080` (SOCKS) или
  `<phone-ip>:1081` (HTTP). См. раздел «Почему для раздачи другим устройствам
  используются порты прокси».
- Смена режима или переключателя раздачи применяется при следующем
  подключении; текущий сеанс сам не перезапускается.
- В режиме прокси нет kill switch и маршрутизации по приложениям.
